# Task Tracking

Use exactly one file per feature, bug, or meaningful outcome:

`task-{short-kebab-case-name}.md`

## Lifecycle

```text
proposed -> ready -> in-progress -> blocked -> completed
```

## Required contents

Every task contains:

- Outcome and background
- Requirements and exclusions
- Observable acceptance criteria
- Documents the agent must read
- Implementation checklist
- Dated progress notes
- Material decisions and blockers
- Documentation impact
- Actual verification results
- Completion summary and remaining risks

Search for an existing task before creating one. Do not make separate plan,
tracking, implementation-summary, testing-report, or completion files.
